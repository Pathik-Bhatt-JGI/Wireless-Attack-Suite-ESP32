ROOT CAUSE:
════════════════════════════════════════════════════════════════════
The code was calling ble_gap_adv_stop() without checking if the
BLE stack was initialized first. This caused a null pointer crash.

The error "BTDM_INIT: esp_bt_controller_rom_mem_release already 
released" indicates the BT controller wasn't properly initialized.

FIX APPLIED:
════════════════════════════════════════════════════════════════════
Added a check before calling ble_gap_adv_stop():

BEFORE:
    s_keyboard->begin();
    ble_gap_adv_stop();  ← CRASH HERE if BLE not initialized
    vTaskDelay(pdMS_TO_TICKS(100));
    ble_gap_adv_start(...);

AFTER:
    s_keyboard->begin();
    
    // Only stop advertising if BLE is already initialized
    if (ble_hs_is_enabled()) {
        ble_gap_adv_stop();
        vTaskDelay(pdMS_TO_TICKS(100));
    }
    
    ble_gap_adv_start(...);
