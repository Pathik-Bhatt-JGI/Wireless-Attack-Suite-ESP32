❌ PROBLEM #1: "WPA Handshake shows EAPOL 3/4 then ESP32 restarts"

✅ QUICK FIX:
   This is OUT OF MEMORY crash!
   
   Do this RIGHT NOW:
   1. Use external 5V power (not USB from PC)
   2. Don't use OLED display during handshake
   3. Reduce capture time to 30 seconds only
   
   The handshake WAS captured before crash!
   Next time, power off RIGHT when you see "EAPOL 3/4"
   The file might be saved already.

❌ PROBLEM #2: "PMKID runs forever, must power off to stop"

✅ QUICK ANSWER:
   This is a BUG in the firmware!
   
   Two options:
   
   Option A - Keep web browser open:
   → Before starting attack, open http://192.168.4.1
   → Keep that browser tab open
   → Use "Stop Attack" button when needed
   
   Option B - Use timeout:
   → PMKID should finish in 10-15 seconds normally
   → If it says "power off to stop", just wait 2 minutes
   → Then power cycle ESP32
   → Check if file was created

❌ PROBLEM #3: "Deauth not working at all"

✅ DIAGNOSIS:
   Need to check why. Run serial monitor:
   
   idf.py -p COM3 monitor
   
   Start deauth and look for:
   ✓ "Deauth started on channel X" = Working
   ✗ "Channel switch failed" = Not working
   ✗ "Failed to send packet" = Not working
   
   MOST COMMON CAUSE:
   → You're testing on iPhone or new Android = They ignore deauth!
   → Test on OLD Android phone (2018 or older)
   → Or test on IoT device, smart TV, etc.
   
   Modern devices (2019+) have protection against deauth.
   This is NORMAL! Not your fault!

✅ "PROBE ATTACK" - This IS Working Correctly!

What you see:
   "ch: 5" = Channel 5 (normal!)
   "found airtel" = Found network named "airtel"
   
✅ THIS IS CORRECT BEHAVIOR!

What it means:
   → "ch: 5" = ESP32 scanning WiFi channel 5
   → "found airtel..." = Someone nearby connected to Airtel WiFi before
   → It cycles through channels 1-13
   → Shows networks that devices remember
   
   If you see network names appearing = IT'S WORKING! ✅
   
   The probe attack reveals WiFi history of nearby devices.
   Every network name you see = Real network someone connected to!

❌ PROBLEM #4: "BT Payload crashes, display restarts"

✅ QUICK FIX:
   Bluetooth needs MORE POWER!
   
   Do this:
   1. Use 5V 2A power adapter (not USB from PC)
   2. Or use powered USB hub
   3. Or better quality USB cable
   
   Temporary workaround:
   → Disconnect OLED display
   → Try BT payload again
   → Should work without display
   
   If still crashes:
   → Power supply is too weak
   → ESP32 needs minimum 500mA for BT
   → PC USB often gives only 200-300mA

📋 WHAT EACH ATTACK ACTUALLY DOES:

WPA Handshake:
→ Captures WiFi password handshake
→ Kicks device off WiFi
→ Captures reconnection data
→ Saves to file for cracking

PMKID:
→ Gets password hash from router directly
→ No devices needed
→ Very fast (10 seconds)
→ Some routers don't support it (normal)

Deauth:
→ Kicks devices off WiFi
→ Modern devices ignore it (2019+)
→ Test on old devices only

Probe Attack:
→ Shows WiFi history of nearby devices
→ "ch: 5" = channel scanning (normal!)
→ "found airtel" = real network found (working!)

BT Payload:
→ Acts as Bluetooth keyboard
→ Auto-types when paired
→ Needs more power than WiFi
